hot-news 配置帮助

首页控制面板状态
整体流程 热榜来源 RSS 订阅 自定义订阅 筛选 AI 配置 推送通道 QQ 机器人 存储与备份 定时与触发 数据保留

整体流程

每 15 分钟触发一次调度，按各模块自己的时间判断是否执行：

  • 抓取热榜（按「间隔分钟」判断是否到点）→ 存 D1
  • 拉取 RSS 订阅 → 解析新条目 → 存 D1
  • 自定义订阅（按各自拉取时间判断）
  • 筛选（关键词 / AI）→ 匹配今天的热榜与 RSS
  • AI 分析（每天一次，输出每日总结）
  • 推送 → 所有已配置且填好的通道
  • 归档 & 备份 → S3 原始数据 + 每日备份

配置保存后立即生效；「立即运行」可手动触发一次完整流水线。

热榜来源（热榜 Tab）

内置 6 类平台模板：B站 / 微博 / 抖音 / 小红书 / Telegram / 自定义。逐条添加来源：

字段说明
id唯一标识，如 bilibili，用于分组与存档文件名
名称首页显示的标题，如 B站热门
域名校验可选；抓取时校验响应域名，防伪造/改源
抓取间隔：整体控制（默认 60 分钟）。设为 15 则每轮调度都抓取。

抓取失败不会中断流水线，会在概览的错误列表里显示。

RSS 订阅（RSS Tab）

两种方式：

  • 从热榜平台添加：直接在热榜 Tab 的平台里选，自动生成平台热榜 RSS，内容自动同步。
  • 添加 Feed：任意 RSS/Atom 源（id、名称、URL）。

支持 <rss> 与 <feed> 两种格式，自动去重只入库新条目。

公开访问：平台热榜 RSS 为 /rss/hot/{平台}.xml（如 /rss/hot/bilibili.xml）；自定义 Feed 为 /rss/{feed_id}.xml；汇总页 /rss。

有些源需要 UA 或防反爬，抓取失败会在错误列表显示原因。

自定义订阅（自定义订阅 Tab）

两种订阅方式，统一进入「订阅必达/订阅更新」报告：

  • 热榜平台：从热榜列表里直接选，订阅即生成 /rss/hot/{平台}.xml，内容来自热榜抓取。
  • 网址 / RSS：粘贴任意 RSS/Atom 或网页地址，自动识别解析。
字段说明
显示名称订阅名，如 早报
拉取时间点每天执行的时刻，如 08:00；多个用逗号分隔；留空=随调度拉取

旧版「平台类型」已移除：B站/抖音/微博等账号订阅的解析能力仍保留在服务器端，但面板统一为「热榜平台 + 网址」两种清晰方式。

筛选（筛选 Tab）

决定哪些新闻进报告/推送：

  • 关键词模式（默认）：标题命中关键词即入选，排名高亮阈值 控制排在前几名的重点标色
  • AI 模式：按「兴趣描述」让 AI 打分，高于「最低分数」入选
关键词每行一个，回车分隔；max_news_per_keyword 限制每个关键词最多几条。

AI 配置（AI Tab）

默认使用 Cloudflare Workers AI（无需任何 Key，用账户额度，每天分析一次）。

通道说明
workers-ai默认。模型名填 @cf/meta/llama-3.1-8b-instruct；可用模型见 Cloudflare 控制台 Workers AI
openai外部 API（DeepSeek/OpenAI 等）：填 api_base + api_key + model
  • AI 每日分析：每天第一次调度时对当日热点生成总结，随推送发出
  • AI 筛选：筛选 Tab 选「AI 模式」后生效
  • 「检查 AI 可用性」按钮可实时验证配置

QQ 官方机器人（图文教程）

QQ 推送用的是 QQ 官方机器人（q.qq.com），不是 QQ 互联（connect.qq.com，那个只能做 QQ 登录）。

一、注册机器人

1. 打开 https://q.qq.com，注册开发者（个人主体即可）
2. 必须完成「超级管理员绑定」：填姓名、身份证号、手机号（需与运营商实名一致）→ 用本人 QQ 扫码 → 人脸验证。绑定完才能继续
3. 应用管理 → 创建机器人 → 填写资料 → 拿到 AppID 和 AppSecret

二、配置事件回调

4. 机器人管理端 → 开发设置 → 事件订阅 → 选「Webhook 回调」→ 地址填：https://news.zjkl.qzz.io/qq/event
5. 订阅事件：勾选「C2C 消息事件」（私聊）和「群聊消息事件」（以后拉群用）

三、获取 openid 并测试

6. 在 QQ 里给机器人发一条私聊消息（如「hi」）
7. 面板 → 推送 → QQ 卡片 → 点「刷新 openid」→ 复制「单聊: 一串id」
8. 目标类型选「单聊（私聊）」，目标 ID 填那串 openid，保存 → 发送测试
单聊主动消息仅限「最近 48h 内有互动」的用户，所以先发消息、再立刻测试。
测试报 QQ 11294 等错误码时，把错误码记下来对照 QQ 官方文档；常见原因：机器人未入群/未发过消息、openid 填错、能力未开通。

目标类型说明

类型目标 ID 填什么前提
单聊（c2c）用户的 user_openid（刷新自动记录）对方 48h 内有互动
群群 group_openid（群里有人发言后自动记录）机器人已入群
频道频道的 channel_id（数字）机器人已加入频道

存储与备份（存储备份 Tab）

S3 兼容对象存储

用于原始数据归档 + 每日备份。以 Cloudflare R2 为例：

  • 控制台 → R2 → 创建存储桶 → 拿到 Endpoint（https://xxx.r2.cloudflarestorage.com）、Bucket 名
  • 创建 API Token（编辑对象存储）→ 拿 Access Key / Secret Key
  • Region 填 auto

每日备份

到点把当日全量数据导出为 full.json + 报告 report.md 上传到 /Daily backup/YYYY-MM-DD/。保留天数自动清理旧备份。

不配置 S3 也能正常跑（只用 D1 存储），只是没有对象存储归档。

定时与触发（高级 Tab）

  • 定时调度：固定每 15 分钟一次（*/15 * * * *），各模块内部判断是否到点
  • 手动触发：概览页「立即运行」；或给 POST /api/pull 带请求头 X-Pull-Key: 密钥（可在高级 Tab 设置），适合外部 cron 调用
  • 站点标题 / 时区：影响首页标题与日期显示

数据保留

D1 里热榜与 RSS 数据按天分区，超过保留天数（默认各 30 天）会被自动清理。想保留更久就调大天数；S3 备份不占用 D1 配额。
